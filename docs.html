How AXELR AI actually works

No marketing haze, no fabricated endpoints. This page describes the pipeline that runs on every request, the three workspaces, the five differentiators that aren't rebranded ChatGPT, and the honest limits of each tier.

01 — Under the hood

How Axelr works #

Every request flows through the same six-stage pipeline. The order is load-bearing — semantic caching runs before memory recall, and memory recall runs before any provider is contacted. That is why a repeat prompt returns in roughly 14 ms without ever touching a language model.

info
Providers currently wired: Groq, Google Gemini, Cloudflare Workers AI, OpenRouter, Mistral, HuggingFace, GitHub Models, NRouter, TextCortex. Rank is recomputed at runtime from per-provider latency percentiles held in Redis.

Circuit breakers, not retry storms

  • Every provider and every (provider, model) pair owns an independent breaker.
  • Rate-limit failures (HTTP 429 / 402) open the breaker for 30 minutes.
  • Ordinary failures open it for 60 seconds after three consecutive errors.
  • The winner is always the least-recently-failed provider, not the least-recently-used.
02 — Workspaces

The three workspaces #

A workspace is not a skin. It rewrites the system prompt, the default task type, the file types accepted, the provider allow-list for your tier, and the daily quota counter it debits. Auto-detection exists — upload a CSV in Core and Axelr offers to switch you to Data. You can pin the workspace in Settings if you'd rather it never did that.

What actually changes per workspace

  • System prompt — Data gets an analyst prompt, Design gets a senior frontend engineer prompt, Core gets a generalist prompt.
  • Sampling — temperature and max_tokens come from WORKSPACE_LLM_CONFIG. Data runs cooler, Design runs warmer.
  • Critic pass — code-bearing responses pass through code_guard; on a syntax or score failure self_healer re-rolls exactly once.
  • Structured output — Data can emit [JSON-DATA]…[/JSON-DATA] blocks that the UI renders as a table or chart and offers as CSV.
03 — Differentiators

What's different #

1 · AHE — Anti-Hallucination Engine

When structured extraction is requested, AHE builds a deterministic verifier DAG over the retrieved fields. If a field cannot be proven from the source document it is returned as null with a machine-readable reason — never invented. AHE failures serialise as structured objects, not as HTTP 500s.

2 · Context-aware semantic cache

Most caches key on the raw prompt string. Ours keys on the meaning of the prompt in context. The same question asked after a different conversation will not hit the cache, because the last two turns changed — which is exactly why we can cache aggressively without ever returning a stale answer.

3 · Touch-Fix

Paste an error message next to a generated code block and TouchFixEngine returns a patched version. It replays the prompt that produced the code, injects the error as context, and routes the result back through the critic pass. If the fix still doesn't compile it is reported as a failure — never silently shipped.

4 · Deep-Think

Deep-Think expands a request into an explicit reasoning plan before any provider is contacted. The plan is streamed into the thinking panel so you can watch the shape of the answer form, then collapsed into a single response. It costs more tokens and is therefore counted as one action — the same as a normal turn — but it does not bypass tier quotas.

5 · Search

Search runs an explicit retrieval pass before generation when the prompt references something time-sensitive or externally verifiable. Retrieved spans are attached to the context block with their source URLs, and AHE treats them as first-class evidence — a claim without a retrieved span is refused the same way an unsupported field is.

warning
Not on this list: a public webhook API. It exists internally and mounts at startup when available, but it is not a stable public contract — no API keys, no rate-limit SLA, no versioning promise. We won't write docs for something we can't support.

05 — Comparison

Axelr vs ChatGPT #

1 · A cascade, not a single backend

ChatGPT serves from one backend. Axelr routes across nine-plus providers with per-provider and per-(provider, model) circuit breakers. When Groq is rate-limited, Gemini is already warm. When Gemini errors, OpenRouter is next. A single provider outage never becomes a product outage.

2 · Local Twin fallback, honestly labelled

When every remote provider is down — all breakers open, keys missing, or TTFT thresholds tripped — Axelr can still answer from the local Twin Engine. If the engine isn't loaded either, the pipeline returns a response explicitly marked [stub]. It will never fabricate an answer, and downstream code treats a stub as a hard failure rather than rendering it as a normal reply.

3 · Workspace-specialised prompts and task types

A Data request is task_type="extraction" with an analyst prompt and a critic pass that verifies every extracted field. A Design request is task_type="frontend" with a senior-engineer prompt, code_guard syntax scanning, and an optional self_healer re-roll. There is no generic assistant mode glossing over the task.

06 — FAQ

Frequently asked questions #

Do you offer a public API?

Not yet. Internally the routers exist (routes_core.py, routes_agents.py, routes_billing.py, routes_admin.py) and a webhook pipeline mounts at startup when available. But there is no public key system, no published rate-limit SLA, and no versioning guarantee.

When a public API ships, this page will say so and there will be a real reference for it.

Why do I have to pick a workspace?

Because each workspace changes real behaviour: system prompt, default task_type, accepted file types, provider allow-list for your tier, and which daily quota counter gets debited.

Auto-detection exists — upload a CSV in Core and Axelr offers to switch you to Data. If you'd rather it never did that, pin the workspace in Settings.

What's the real difference between Explorer, Pro and Business?

Explorer gives you 5 data / 3 design / 10 core actions per day against the free-eligible provider pool. Pro unlocks the extended pool and roughly triples the allowance. Business unlocks the full pool, the multi-agent orchestrator, and the largest file limits.

The full matrix is above — it is generated from the same JSON the checkout page bills from.

Is my data used for training?

No. Sessions are stored per-user and keyed by your user id. The semantic cache key is derived from your prompt, workspace, task type and the last two turns of your own conversation — it never crosses users.

When a provider is called the request goes directly from our server to that provider. We don't insert a middle-man training layer, and we never send your history to a provider that isn't handling your current request.

What is the Twin Engine and why does it matter?

The Twin Engine is a local inference engine that takes over when every remote provider has failed — all breakers open, no keys configured, or TTFT thresholds tripped on the whole fallback chain.

If the engine itself isn't available (weights not loaded, host out of memory) the pipeline returns a stub explicitly marked [stub]. Downstream code treats that as a hard failure and surfaces it — it never renders as a normal answer.

How do I upgrade, and how fast is activation?

Upgrades are manual UPI. You pick a tier, scan the QR (or open your UPI app), pay, and submit the 12-digit UTR on the checkout page. A human verifies it, typically inside an hour, and access is applied to your account automatically.

If verification takes longer than an hour, email axelrsupport@gmail.com with your UTR.
